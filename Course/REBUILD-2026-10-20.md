## MY ERROR: created lessons lost their HTML (found by Steve, fixed 2026-10-20)

**What happened.** `update_course_content` strips HTML from a lesson body when the lesson is being
CREATED. Headings, lists and paragraph tags were removed and the whole body collapsed into a single
<p> with bare newlines, which browsers do not render. Every lesson I created this session rendered
as one run-on paragraph. Updating an EXISTING lesson preserves HTML perfectly.

**How it got past me.** I verified that every write returned success and that the course structure
was correct. I never re-read the body of a lesson I had created. Steve found it by reading the
course as a member would.

**Fixed by re-sending each affected body as an update.** 15 lessons:
2201292321 (When To Stop And See Your Doctor), 2201292342 (Week 3 pattern page),
2201292365-369 (five shopping lists), 2201292974-979 (five meal plans),
2201293986/987/988 (the three Reintroduction Fortnight lessons).

Not affected, because they were created and then later updated with a new body:
2201292320 (How This Course Works), 2201292374 (Supplement Reference), 2201292375 (When You Have
Finished). All three verified as correct HTML.

**Verified after the repair** by re-reading bodies, not by trusting the success response:
2201292321 and 2201292320 both confirmed as proper HTML with headings and list markup intact.

**Rule for anyone working on this course through the API:** after creating a lesson, always send a
second call that updates its body, and re-read it. A success response means the row saved, not that
the markup survived.

## 2026-10-21: Tables rendered as blank space

Steve sent a screenshot of Your Reintroduction Tracker (2201293987). The header read as one run-on
line, "Food Date tested Same day Next day Day 3 Verdict", followed by a large empty gap.

**The markup was fine.** The table, its header row and six rows of `&nbsp;` cells were all present
and correct. The course theme simply draws no borders on table cells and gives them no padding, so
a header row collapsed into run-on text and six rows of empty cells rendered as nothing at all.

This is a different failure from the create-strips-HTML bug. Nothing was lost in the write. The
markup was valid and the renderer gave it no styling, which is why it passed every check I had been
making: re-reading the body would never have caught it. Only looking at the page does.

**Fixed with inline styles on every cell**, since that is the technique with the fewest unknowns:

- 1px #DDD8CE borders, #F5F1EA header background, 10 to 12px cell padding, `vertical-align:top`
- each table wrapped in a `<div style="overflow-x:auto">` with a `min-width` on the table, so six
  columns scroll on a phone instead of crushing
- a worked example row added above the blank tracker, so the expected level of detail is obvious
- the blank tracker went from six rows to eight, with 22px cell padding so it is usable on paper

### Why not a stylesheet

A `<style>` block and `class` attributes do survive the API write. I tested it on a draft lesson,
and both came back intact on re-read.

That only proves the API stored them. It does not prove Kajabi's renderer serves them to the member
page, and `class` plus `<style>` is exactly what the Encore theme's text block sanitizer strips on
the home page. Inline styles are proven to store and are the same mechanism already working
elsewhere, so the tables use those. Worth retesting if a future page needs many tables, because the
inline version is verbose.

Four unstyled tables, and the worst affected page in the course, because its cells hold real

### Defects caught by rendering the PDF and looking at it

Worth recording, because none of these would have shown up in a success response:

- **reportlab's `Tc` leaks.** Setting character spacing inside a text object persists into every
  later text operation on the page, so the body copy came out letterspaced and, because
  `stringWidth` does not know about it, overran the right margin and clipped mid-word. Fixed by
  resetting char space inside the same text object.
- **The Date tested column was narrower than its own header**, so it collided with Same day.
- **The closing line on page 2 ran off the page** and left a dead gap mid-page. Rewritten as a
  sage band placed under whichever column runs longer, with the text wrapped.
